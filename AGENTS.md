# Sightglass repository agent contract

## Authority and current scope

- `docs/SPEC.md` is the accepted product/engineering specification, revision v0.4; `docs/RETRIEVAL-SPEC.md` is its accepted SG-051–059 extensions, including the explicitly selected URL-egress exception and selective-residency/offline-slimming contract.
- `docs/IMPLEMENTATION-PLAN.md` is the complete M0–M7 coverage ledger. A milestone tranche never narrows the specification.
- `docs/current-state.md` owns public source/candidate/release status and blockers. Installation-specific account authorization, live receipts, host details and private continuity remain outside Git.
- The private source remains the editing authority; `IndelibleVivi/sightglass` is its maintained clean public projection. Export only publication-reviewed tracked paths from one exact source commit, with no private Git ancestry. Keep the include manifest and source/public commit mapping in private operator records; compare the complete path set and file bytes before every export. Only `docs/current-state.md` may differ for checkout-specific publication/CI state; reconcile other edits in the canonical source before publishing. Public `main` uses the existing standard GitHub-hosted gates, never real-account jobs.
- `LICENSING.md` owns the exact AGPL-3.0-only software/functional-material and CC BY-NC-SA 4.0 independent-content scopes. Preserve `NOTICE.md` and the WGO attribution; never apply the independent-content restriction to AGPL-covered software. Installed dependencies retain their own terms.
- `MANIFEST.in` owns the public source-distribution include boundary. Packaging changes must retain the Swift/helper/build/contract source and license/provenance files, and inspect the actual wheel/sdist payload. Never bundle runtime state, credentials, real-account data or the unaudited SILK codec.
- M0–M4 synthetic behavior remains the deterministic regression baseline. Real source access requires explicit operator authorization for one configured local macOS WeChat account and is allowed only through the configured `macos-wechat` provider and local private runtime. Never inspect or expose unrelated accounts or anything excluded by current policy. Repository instructions do not grant access to a user’s account.

## Source ownership

- `src/sightglass/contracts/` owns versioned external and internal data contracts.
- `src/sightglass/voice/` owns the voice batch/transcript domain service and repository (server-side verified inputs; SQL lives in `voice/repository.py` as a user-specified exception for this task), plus the local recognizer: verified capture, the bounded SILK→PCM decode child, and the Apple `SpeechAnalyzer` helper runner. `src/sightglass/runtime/voice_setup.py` assembles that recognizer for one daemon configuration; production code never fabricates a fake one.
- `scripts/` owns operator-facing local build steps. `scripts/compile-voice-helper.sh` compiles the Swift helper into a private path and does nothing else — it installs no LaunchAgent, starts no tunnel, and fetches nothing.
- `swift/sightglass-transcribe/` owns the Swift helper source that links the on-device `SpeechAnalyzer`/`SpeechTranscriber` APIs.
- `src/sightglass/source/` owns the provider registry, provider descriptors, source inventory, typed `catalog`/`conversation`/`message`/`resource` sessions, WAL-aware dependency validation, source parsing, overlap reconciliation, and source identity evidence. `SyntheticSourceProvider` owns private fixture copies; `MacOSWeChatSourceProvider` owns native read-only SQLCipher access. A native narrow session captures each main/WAL revision before pinning its read transaction, checks it after opening and on exit, and validates only its recorded database/file read set; a read-opened zero-byte WAL is equivalent to an absent WAL. Catalog scope retains full-snapshot validation. Native v6 context reconciles retained server identities across every serving shard before resource hydration, and its implementation revision fences pre-fix materialized projections through the existing epoch. Shared native catalog handles reserve users before waiting, retire old same-path identities, and cap idle handles at 16 with a 60-second age threshold; physical close runs outside the registry lock. Active/reserved users and session-owned handles must never be evicted. Providers return evidence; they do not choose reader policy. A provider may set `message_sender_evidence_complete` only when every returned `SourceMessage` already carries the stable sender/current-label evidence needed for admission; otherwise ordinary message reads retain the separate roster scan.
- `src/sightglass/residency/` owns the independent keep/recent/on_demand decision, settings, read leases and resident lifecycle metadata/SQL; ReaderPolicy remains the access authority. Every foreground/background admission consumes that decision. New configurations/conversations default on_demand; deterministic fixtures requiring continuous collection must explicitly select keep. Existing stock stays protected until exact operator release preview/apply. Observed traversal progress is distinct from resident coverage; expiry must not trigger automatic refill or manufacture updates. Pending exact replay, actor/alias/correction/reader state and exact active resource/voice dependencies stay protected. Residency grants no semantic egress or remote deletion.
- `src/sightglass/storage.py` owns process-wide owned-file accounting, reservations, soft/hard admission and maintenance allowance. All daemon growth paths share that instance; status/replay must remain available under pressure. It is backpressure, not an OS quota.
- Schema v10 adds resident body availability, independent settings/ownership/totals, exact read leases and restart-safe body-release jobs. `model/resident_read.py` owns the ordinary local body-read predicate, excluding expired temporary bodies and active release jobs before physical cleanup completes. Catalog readiness may settle on_demand scope without claiming tail/history coverage; inbox is explicitly resident-only. Historical jobs select only explicitly enabled keep conversations.
- `src/sightglass/model/compact_candidate.py` owns stopped-only schema 9/10 frozen input, exact compressed recovery, resumable SGOC/release/FTS candidate conversion and streaming durable rowid/sequence/byte verification. Explicit whole-stock release binds one exact source revision and resolves membership against its frozen transaction with bounded memory; active dependencies remain pinned. Normal WindowDB startup rejects legacy schemas before DDL. `model/migrations.py` retains historical fixture callers only; it is not a current production startup path.
- `src/sightglass/runtime/paired.py` owns the atomic runtime/config/DB selector and recovery journal; `runtime/paired_state.py` owns independent private-state cloning and internal path relocation. Pending spool, referenced CAS, token-secret and known sidecars must belong to each pair's own namespace so new ACK/cleanup cannot damage old rollback. The default `<data_dir>/voice/sightglass-transcribe` helper is an independently copied private executable; first activation checks source and target provenance, while an explicit external helper path remains external. Source bindings remain unchanged and private. Stopped-only same-schema `--copy-current` relocation reuses exact byte-copy verification and independent state cloning, without rebuilding the database. No pair or recovery retirement is implicit.
- `model/current_body.py` owns the normalized current-body/search/card/message view and deterministic legacy-column normalization. Ordinary text lives in `messages.text`; `structured_json` retains the envelope and `search_text` remains only for a distinct search document. Preserve legacy schema-v10 callers until explicit stopped-only compact normalization and operator acceptance; no startup rewrite or historical-observation body fallback. Representation changes must preserve episodes, canonical matching and semantic recipe inputs. Compact construction/verifier may project only declared duplicate-field transformations while frozen recovery stays byte-exact; conflicts and corrupt mappings must fail closed. Progress/receipts bind `CURRENT_BODY_VERSION`; an older transformation requires a new candidate path, never mixed chunks.
- `src/sightglass/model/` owns `window.db` schema, migrations, SQL, and the explicit compressed backup/restore lifecycle. Schema v5 adds the materialized message projection epoch and first/current observation sequence used by the local read plane; schema v6 adds durable leased/fenced resource-derivation jobs; schema v7 adds the account/time message timeline that drives bounded account-wide resource discovery; schema v8 adds versioned links, the casefolded lexical trigram index and its derived-index/projection state; schema v9 adds trusted contiguous source coverage, validated disjoint read windows and a durable observation-maintenance checkpoint. SQLite must keep foreign keys on, WAL, busy timeout, schema version, private permissions, partial unique indexes for nullable scope, and separate catalog/shard/backfill/timeline/update/delivery/resource-job/derived-index state.
- `src/sightglass/source/message_identity.py` owns the canonical native message token used by both provider identity and explicit server-ID reply targets. Reply display names never merge participants.
- `src/sightglass/model/backups.py` owns durable restore journal/namespace recovery; `WindowDB` and stopped-only CLI backup entry points invoke recovery before opening the database. `runtime/control.py` owns terminal-delivery spool cleanup under the pending-publication writer fence.
- `src/sightglass/source/links.py` owns local-only URL extraction and bounded hostname candidate evidence for one observed message (`LINK_EXTRACTION_VERSION`); `src/sightglass/model/links.py` owns the versioned link store, atomic admission/correction, fenced historical backfill and rebuild intent. No step fetches, redirects or resolves a URL over the network.
- `src/sightglass/model/lexical.py` owns the casefolded trigram candidate index (`LEXICAL_RECIPE`) used only as a necessary-condition accelerator; canonical literal AND matching against the current source remains authoritative. `src/sightglass/reader/retrieval.py` owns `find_links`/`retrieve` candidate recall, transparent rank fusion and the versioned link projection.
- `src/sightglass/runtime/derived_worker.py` owns the bounded (limit 100) local derivative backfill that never opens the source, advances reader state or schedules voice/previews, and suspends under storage pressure. `src/sightglass/semantic/` owns the optional BGE-M3/Vectorize adapter, versioned message recipe, durable private sidecar and canonical candidate admission; `runtime/semantic_worker.py` owns its independent bounded publication loop. Config defaults disabled and requires exact account/conversations plus external-data consent. The Apple encoder retains its existing benchmark caller only. `examples/benchmarks/cloudflare_semantic.py` owns the separately authorized synthetic-only Workers AI/Vectorize experiment; it never reads a Sightglass config/source/runtime. Its private CF config, credentials, raw vectors and receipts remain outside Git. Semantic message recipe v2 encodes distinct nonempty canonical fields only; unknown display placeholders are ineligible. A prior recipe sidecar fails closed and needs the documented stopped-only replacement. Materialized neighbor reads seek the existing canonical timeline index with source-time bounds; snapshot correction checks seek observations after the signed watermark.
- `src/sightglass/resources/` also owns native-image decoder provenance: a source-original/thumbnail binding for a native image is admitted only when a recorded derivation matches the provider decoder implementation and the captured resource revision, so an older unversioned native image object is invalidated and its preview regenerates.
- `src/sightglass/model/observation_maintenance.py` owns bounded, content-free consistency inspection and restart-safe batched current-projection repair. Observation versions represent state episodes: A→B→A advances twice even when a payload was seen earlier; identical current content may remain idempotent. Repair preserves immutable historical observations and identity corrections, appends version evidence or invalidates unsupported projection, and fences affected cursors/derivatives. `runtime/daemon.py` and `cli.py` expose only operator inspect/repair entrypoints.
- `src/sightglass/model/storage_diagnostics.py` owns quick capacity/page summaries and explicitly requested deep phases. Default explain never performs whole-history counts or recursive CAS reconciliation; deep requests retain completed results on their server deadline or client disconnect and release each statement's read view. `storage.py` remains the admission/physical-floor authority.
- `src/sightglass/model/observation_codec.py` is the only observation encoder/decoder. New `parsed_json` values are versioned BLOBs; legacy TEXT stays readable with unchanged raw payload digests. No startup bulk rewrite/VACUUM. Legacy stock is protected until explicit scope preview/apply; only approved cache lifecycles may expire derived/source-body copies, preserving durable identities/state and active dependencies. Identity correction must decode through this path; pending replay uses its independent immutable spool.
- `src/sightglass/reader/` owns hydrate, identity projection, labels, discovery, context/search/update semantics, signed cursor scopes, and exact delivery payloads. Current-epoch message observations may establish local message/context readability independently of tail completion; historical reads must not mark a catalog conversation handled. Validated unfiltered source pages record their observed continuity windows; foreground recent refresh never moves an existing contiguous sync frontier over an unobserved gap. Legacy complete flags are unproven until bounded source revalidation, and materialized context must respect validated window boundaries. Local-result/error routing must not acquire source foreground ownership; execution still rechecks its premise. Explicit `read_messages(refresh=True)` uses the canonical bounded source path, rejects updates/cursor combinations, and never silently falls back to stale materialized results.
- `src/sightglass/resources/` owns bounded V2 decode, source-original/thumbnail variant handling, MIME/content validation, safe image/PDF/text/Office/structured/archive/media processing, stage coalescing, durable resource-job semantics, and the private content-addressed object store.
- `src/sightglass/runtime/search_preparation.py` owns ordinary-search and cold-discovery durable private job/token state, same-scope single-flight and cancellable bounded execution. The sidecar adds no window schema; query text is never persisted. Reader source preparation checkpoints only admitted conversations, re-scans interrupted leases and still requires fresh canonical result validation. Providers own the bounded positions/payload iterator and selected logical-generation evidence; they do not own reader policy. Cold discovery uses bounded physical-row candidate pages, canonically reconciles matching identities before admission, admits matches plus bounded context, and uses separate idempotent continuation tokens for another attempt. Polls/result pagination remain local; reaching traversal bounds never claims one atomic source snapshot.
- `model/worker_schedule.py` owns read-only queue/deadline/scope SQL; `runtime/worker_wait.py` owns bounded retry/lease/fallback waits. Each lane owns its Event and clears it before probing durable state. `WindowDB.wake_after_commit` emits best-effort queue notifications after the outer commit and writer release, discarding rollback notifications; it is not a durable hook or queue. `runtime/worker_diagnostics.py` owns content-free current versus bounded historical error type/public-location and work/wake/idle counters. Empty recovery must not take a writer; actual recovery/publication still rechecks durable fences in the writer.
- `src/sightglass/runtime/` owns private config, Keychain-backed secrets, local IPC framing/authentication, daemon lifecycle, independent bounded work lanes, the durable resource worker, and operator-only mutations. `runtime/daemon.py` owns explicit operator-only, database-free operation-position sampling; only public module/function/line locations may be projected, never frames, locals, arguments or private paths, and ordinary reader/MCP status never samples stacks. `runtime/storage_history.py` owns the bounded content-free daily storage sidecar and exact 7/30-day growth projection; it does not change `window.db` schema or make `storage explain` mutating. `reader.timezone` owns new response time projection; it never changes source timestamps, native attachment month lookup, cursor positions, or already-spooled deliveries.
- `src/sightglass/policy/` owns server-side reader identity and conversation authorization.
- `src/sightglass/mcp/` is a thin bridge: validate/project/call service only. `mcp/tools.py` owns the shared public tool declarations; daemon proxies and catalog schemas derive from them. `mcp/projection.py` owns format-only brief/diagnostic projection and continuation hints; `reader/response_budget.py` carries request-local targets into the existing reader page/cursor allocators. Exact update payload replay remains outside profile trimming. Do not put source SQL, parsing, identity merge, or policy rules in MCP.
- `tests/fixtures/` owns deterministic synthetic-source builders. Generated databases remain ignored and disposable.
- `scripts/benchmark-compact-candidate.py` owns the 100k generated-provider/full-WindowDB lexical parity, episode/FTS churn and actual footprint/peak proof; it never consumes a configured account or runtime. Use an explicit synthetic scratch destination and keep receipts outside Git.

## Installation ownership

- The SG-059 schema/backend conversion is stopped-only and explicit; normal WindowDB startup must not bulk-convert a legacy database. Candidate and exact recovery share one frozen committed input. Preserve all durable rowid-to-identity mappings and sqlite_sequence high-water marks. External candidates copy to same-filesystem staging before verified/fsynced namespace activation; runtime and DB selection are a pair. All workspace/backup/temp/WAL bytes and physical free floor are accounted; do not retire the old active DB to force headroom. Source/synthetic completion never authorizes real-account candidate construction, cleanup, migration or activation.
- Production uses an isolated non-editable wheel environment with frozen runtime extras and exact source provenance; the editable checkout is development state. Promotion/rollback belongs to the operator under explicit deployment authorization, following `docs/OPERATIONS.md`. Keep live installation manifests, command targets, config backups and receipts outside Git.
- A cleanup must preserve the active production interpreter/environment and a usable previous release plus verified pre-migration recovery point. Real-account backups require an encrypted local volume; owner-private permissions alone do not establish volume encryption. Never infer semantic real-content egress consent from core deployment authorization.

## Hard boundaries

- Config v2 admits only registered `synthetic` or `macos-wechat` providers. Native initialization requires one exact supported, running app/source candidate and a complete page-1-verified key import before activation.
- Never add real user data or credentials—including user paths, source principals, contact labels, message bodies, decoder/signing keys, or local runtime artifacts—to Git. Deterministic fixture values must be unmistakably synthetic.
- Source-backed incomplete and selected-dependency change fail closed. Slow source discovery/read work must not hold the `window.db` writer lock; persistence/admission uses a short transaction whose commit occurs only after final full-snapshot or dependency-session validation. An unrelated unopened shard/WAL change must not invalidate a narrow target read. Current-source responses project only message IDs admitted by that source page. A bounded absence is never deletion/recall evidence. Current-epoch materialized message/inbox reads and authorized CAS hits may continue without a provider snapshot, but must report bounded-stale/local-cache freshness and must not claim live confirmation.
- Canonical participants link only through eligible stable source keys. `public_handle`, labels, avatars, and writing style never merge actors.
- Principal-eligible keys are repository-whitelisted; conversation-local speaker filters preserve key kind, value, and conversation scope. Account self is an account invariant, not inferred only from a roster row or outgoing message.
- Non-text raw transport envelopes and absolute resource paths remain private observation data and never become MCP-visible text/filenames.
- Group card belongs to membership. Current labels cannot be asserted as historical `shown_as` without message-time evidence.
- Reader identity is injected server-side, never accepted from MCP arguments.
- Signed input cursors must stay bound to reader/account/conversation/filter scope. Live/source-backed timeline cursors additionally bind the logical generations of the message shards that actually served that conversation, so an ordinary append survives while selected-shard replacement stales without inheriting unrelated account-wide generations. They still reconcile their opaque position against the current source. Materialized timeline cursors bind projection epoch, observation watermark, policy revision and the append-only identity-correction ledger revision, exclude later appends, and stale on a correction to a row visible at that watermark. Never fall back silently on invalid or stale cursors.
- Updates advance only after ACK. A capacity failure may commit a policy/scope-validated ACK using the maintenance allowance and report `ack_committed=true`; ordinary source failure must still roll it back. Participant/filter-set scopes never advance conversation state. Unacknowledged payloads replay from the private immutable spool; a policy change expires pending deliveries before they can reappear.
- Search candidate recall is not evidence. Return only canonical current-source message IDs admitted under the same snapshot, and never persist natural-language query text in access receipts.
- Resource content is reachable only through a message-bound opaque `resource_id` whose conversation policy is rechecked. Never expose source/cache paths or decoder keys, follow source symlinks/hardlinks, trust declared MIME without sniffing, skip digest verification, or add implicit network fetch.
- A cache-first resource hit must still require current reader authorization, an active canonical resolver, the requested variant, per-read CAS digest/size verification, and a short resolver-revision comparison before derived bindings commit. If a daemon-classified local-only premise disappears, fail closed instead of touching the provider without foreground ownership.
- A cold resource miss must acquire the exact binding-authenticated locator once inside a `resource` session, preserve the existing no-follow/link/digest/file-mutation checks, close the source lease before processor work, and compare the captured resolver revision again inside the short binding-admission transaction. Do not restore the superseded owning-message rehydrate plus second global-snapshot path.
- Resource cache directories stay mode `0700`; objects stay content-addressed, atomic, digest-verified, mode `0600`, and single-linked. Generated previews are not source originals.
- Native image decoder keys are account-binding-scoped Keychain secrets. Enrollment accepts only an owner-private no-follow file or stdin; literal key material is forbidden in argv, output, config, `window.db`, receipts, tests, docs, and Git. A source-kept thumbnail uses the `thumbnail` variant, may satisfy preview, and must never satisfy original.
- Raw link URLs remain private observation data. Only `find_links` and `retrieve` may project the full observed raw/normalized URL, including credentials, port, query, and fragment; this is an explicit owner-authorized egress exception for those discovery results. Ordinary message link projection (`read_messages` `structured.link` and `display_url`) omits raw URL, credentials, port, query, and fragment. No tool ever fetches a URL. Forwarded-chat item projection stays bounded and cannot merge inner display names into canonical participants.
- No WeChat writes, app re-signing, injection, implicit URL/resource network fetch, public listener, or WGO runtime/monitor/digest/bookmark state. The optional semantic lane uses only BGE-M3 + Vectorize and requires explicit operator authorization for the exact source account and conversation list before encoder/query egress. Query inputs and credentials never enter logs/access receipts; remote candidates need current canonical version/policy admission. No automatic index provisioning/deletion. An explicit operator-authorized benchmark may call Workers AI and a dedicated `sightglass-synthetic-` Vectorize index with its fixed generated corpus only; this does not authorize real account text, labels, IDs, URLs, transcripts or resources leaving the local boundary. Private sidecar/config/token remain outside Git. Native DB handles must remain `mode=ro` plus `query_only`; database keys stay in Sightglass Keychain storage and never enter subprocess argv, logs, receipts, docs, tests, or Git.
- Native initialization defaults to a one-conversation selected allowlist. Switching an account to `all_except_denylist` requires that account owner’s explicit operator privacy decision. Keep installation-specific authorization and runtime receipts outside Git. Policy changes must invalidate affected cursors/pending deliveries and remain distinct from source installation or code readiness.

## CI ownership and triggers

GitHub Actions owns CI because native fixture and full Pyright coverage require
macOS. Do not migrate those gates to Cloudflare or change repository visibility
to save minutes. The canonical gate definitions remain in
`.github/workflows/synthetic.yml`: portable checks run on code pushes and PRs;
the unchanged full macOS suite runs on main pushes, PRs, and manual dispatch.
Feature-branch pushes run portable checks until a PR or manual macOS run.
The portable job includes generated residency, offline compact, paired-runtime
and released-observation regressions; it does not open a native account.
Documentation-only pushes/PRs skip both jobs. Manual dispatch can select a ref
once this workflow is registered on the default branch; until then use a PR
for hosted native coverage. Do not promote product source merely to enable dispatch.
No hosted job reads a real account.

## Verification

Sightglass acceptance tests must never select a Pro model. Use the operator-selected ordinary model and reasoning intensity; verify the actual model before submitting each acceptance run. Pro results do not establish ordinary daily-use acceptance, and an unavailable ordinary model is a blocker rather than permission to substitute Pro.

Schema v8 requires SQLite with FTS5 trigram support; the SG-059 contentless-delete target additionally requires SQLite ≥3.43 and an actual capability probe. Preserve detail=none; columnsize=0 is incompatible with this backend. `reader/retrieval.py` version `sightglass.retrieval.rrf-context.v3` expands same-conversation link neighbors independently of the body-radius and resolves explicit reply targets only within hard policy/time/sender scope. `.github/workflows/synthetic.yml` separates portable Linux gates from the full macOS synthetic/native fixture suite; full-repository Pyright runs in the macOS job with all declared extras, while Linux runs compileall/Ruff and the portable suite; neither CI job reads an account. IPC peer identity uses macOS getpeereid or Linux SO_PEERCRED; keep same-owner UID and token checks on both paths, and do not interpret synthetic Linux coverage as native WeChat support.

Run from the repository root:

```bash
uv sync --frozen --extra dev --extra macos-wechat --extra voice
uv run python -m unittest discover -s tests -t . -p 'test_*.py'
uv run python -m compileall -q src tests
uv run ruff check src tests
uv run pyright
git diff --check
```

Native verification additionally requires `uv sync --extra dev --extra macos-wechat`, the encrypted SQLCipher integration fixture, and a content-free live receipt. Never print real titles, labels, principals, message bodies, source paths, database keys, or imported key-map contents while verifying.

Voice verification additionally requires `uv sync --extra voice` and, for real recognition, a helper compiled by `scripts/compile-voice-helper.sh` plus the target language's installed speech assets. Real speech and transcript text must never be committed: the default-skipped real test synthesizes its own audio with `say`, and only synthesized audio may be used. Never commit real SILK/PCM bytes, staging paths, or any transcript derived from real user data.

Run focused unittest modules while iterating. Full M4 completion requires every synthetic integration and contract test to pass after the last relevant edit, including real-process daemon/bridge restart, socket/auth, correction-ledger, cache-control, and pending-delivery recovery checks. Poppler-backed PDF changes also require inspecting at least one rendered fixture page, not only checking the subprocess exit status.

Tests that call a `_decode_child` or helper entry point in-process must restore any process-wide state they mutate (`RLIMIT_FSIZE` in particular); leaking it breaks every later test that writes a file.
