# Sightglass complete implementation plan

## Spec authority

- Canonical specification: [SPEC.md](SPEC.md), accepted revision v0.4. It states the complete product contract, including capabilities not yet implemented.
- This ledger retains the M0–M7 scope and subsequent reader/resource/voice extensions. A milestone slice never narrows the specification.
- [Current state](current-state.md) owns current source and publication status. Installation authorization, account metrics and live acceptance receipts remain in private operator records outside Git.

## Dependency order

```text
M0 contract/provenance → M1 synthetic reader → M2 context/search/updates
  → M3 resources → M4 daemon/control → native provider/SQLCipher
    → M6 separately authorized native acceptance
      → account catalog/inbox + incremental index + local attachments
        → optional M5 WGO adapters and remaining M7 capabilities
```

Source completion never authorizes real account access or deployment. Native initialization keeps its one-conversation allowlist; wider scope requires an explicit operator decision.

## Current source tranche

The 2026-10-05 review follow-up is source-complete and verified by the final
1,128-test suite: residency-cap progress, durable cold-deadline continuation,
cross-shard native context conflict rejection with a v6 projection fence, paired
default-helper relocation, and the first thirteen-tool MCP brief/continuation pass.
Installed promotion, fresh host acceptance and public-root hosted CI remain separate.

The implemented native provider uses source-ID-v2 message identity with parser `sightglass.wechat-parser.v2` and native descriptor `sightglass.macos-wechat.sqlcipher.v6`, source schema-v10 private state, catalog-wide snapshots plus typed dependency-scoped sessions, selected-shard live cursor generations, bounded live-tail polling and resumable historical backfill. Current-epoch ordinary message modes, native inbox and resource catalog read from the materialized local plane with bounded-stale receipts; account-wide resource discovery is driven by the indexed account/time message timeline. Schema v8 adds rebuildable link/lexical derivatives: local-only URL extraction feeds a versioned `message_links` store with atomic admission/correction and fenced backfill, and a casefolded FTS5 trigram index supplies only necessary-condition candidate recall while strict literal/current-source validation stays authoritative. `wechat_find_links`/`wechat_retrieve` preserve reader state; retrieval may add explicitly authorized remote semantic recall to materialized reads with signed scope/version cursors and a signed result continuation; ordinary message link projection stays redacted and no tool fetches a URL. The optional BGE-M3/Vectorize source lane is disabled by default and requires separate exact-scope external-data authorization; its installed activation is not claimed. Known cold/stale message targets use conversation/message sessions, search retains current-source validation, and replay advances only after ACK. Warm resources use authorized, digest-verified cache-first resolution with resolver-revision admission; a cold resource acquires its exact locator once inside a resource session, then processes and admits bindings after the lease closes. Independent runtime lanes protect local reads from source/processor saturation, and long derivations use durable fenced jobs. Optional voice follows verified capture → bounded SILK decode → on-device recognition → fenced commit.

The implementation supports account-wide policy but does not activate it on behalf of a user. Optional media/mapping/image keys and speech assets are installation-specific. Unavailable source bytes remain explicit; there is no network fallback.

## Scope decisions

- Native source reads were implemented ahead of optional WGO knowledge/CAS adapters so the reader has no WGO runtime dependency. M5 remains visible and inactive.
- Catalog/inbox, account policy, incremental history, local rich-file resources and bounded voice work extend the original tranche while preserving the read-only source boundary.
- SG-046 compression preserves protected stock. SG-058/059 separately implement selected residency, bounded temporary-body expiry and explicit stopped-only compact conversion; mode changes do not release legacy stock. Structural content sharing and integer-key rewrites remain deferred for measured benefit. No live/startup bulk conversion is introduced.
- SG-047 changes the foreground route, not source authority: materialized message/inbox and warm CAS hits remain explicitly bounded-stale/local-cache, while search, cold misses, stale semantic epochs and conversation discovery retain source-backed validation. SG-048 narrows known-target and resource source work to its recorded dependencies; genuinely account-wide conversation/search/catalog work keeps catalog scope. SG-049/SG-050 add stage-specific runtime lanes, durable resource derivation, local resource discovery/format negotiation and explicit backup operability without changing source authority or widening policy.
- Menu-bar/local UI, watch workflows, additional source platforms, automatic key refresh and remaining M7 features are not implied by the completed native reader.

## Reading reliability convergence

The [reading reliability decision](READING-RELIABILITY.md) connects SG-047/048/055/057
to the original eight reading journeys. The 2026-10-02 work separates local observed-page
readability from background tail/catalog completion, narrows signed-anchor refresh,
keeps locally decidable errors out of source quiescence, adds an explicit bounded
